# 01-1. 유닛 구조 (interface & implementation) 🧱

> 💡 **초초보자를 위한 한 줄 요약**  
> 델파이 소스 파일(`.pas`)은 **"식당 메뉴판(interface)"**과 **"주방 안의 조리법(implementation)"** 두 영역으로 완벽히 구별되어 있습니다!

---

## 🏬 델파이 유닛(Unit)이란 무엇인가요?

델파이에서 코드 한 덩어리가 들어있는 파일 하나(`.pas`)를 **'유닛(Unit)'**이라고 부릅니다. 

마치 책의 한 장(Chapter)처럼 연관된 코드들을 모아둔 방입니다.

---

## 📑 유닛의 2대 핵심 구역: Interface vs Implementation

델파이 유닛 문서를 열어보면 구조가 이렇게 딱 2개로 나누어져 있습니다!

```pascal
unit Unit1; // 1. 유닛의 이름

interface // ------------------------------ [구역 A: 메뉴판 구역]
// "외부 사람들에게 공개할 함수/변수 이름만 목록으로 보여주는 곳"

implementation // ------------------------- [구역 B: 주방 조리 구역]
// "메뉴판에 적은 함수가 실제 어떻게 동작하는지 진짜 코드를 작성하는 곳"

end. // 유닛의 끝
```

---

## 🍽️ 쉬운 비유로 알아보기

### 1. `interface` (인터페이스 = 메뉴판)
* 식당에 가면 손님이 볼 수 있는 **메뉴판**입니다.
* "우리 집은 김치찌개(함수A), 불고기(함수B)를 제공합니다" 하고 **이름과 가격만 공개**해 둔 것입니다.
* 다른 파일(`.pas`)에서 이 유닛을 불러올 때, `interface`에 적힌 내용만 가져다 쓸 수 있습니다.

### 2. `implementation` (임플리멘테이션 = 주방 내부)
* 손님은 볼 수 없는 **식당 주방 내부**입니다.
* 김치찌개를 끓이기 위해 김치를 자르고 육수를 붓는 **진짜 레시피 동작 소스 코드**가 여기에 들어갑니다.

---

## 💻 실제 델파이 코드 모양으로 보기

```pascal
unit MyMathUtils; // 유닛 이름

interface

uses
  SysUtils; // 다른 부품을 가져올 때 쓰기

// [메뉴판] 외부에 공개할 함수의 이름만 선언!
function AddNumbers(A, B: Integer): Integer;

implementation

// [주방] 위에서 선언한 함수가 진짜 일하는 모양을 작성!
function AddNumbers(A, B: Integer): Integer;
begin
  Result := A + B; // 두 숫자를 더해서 결과를 돌려줌
end;

end.
```

---

## 🎯 초초보자를 위한 핵심 요약

1. **`interface` 아래**: "나 이런 함수 만들 거야!" 하고 **목록 선언만** 하는 곳!
2. **`implementation` 아래**: `begin ... end;` 사이에 **진짜 코드를 지글지글 작성**하는 곳!
3. 유닛의 맨 마지막은 항상 **`end.`** (마침표)로 끝납니다!
